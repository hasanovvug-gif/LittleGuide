## 1. Модель данных и совместимость

- `RhythmEvent` получает `feedType?: 'breast' | 'bottle' | 'solid'` — только для `kind='feeding'`.
- **`SCHEMA_VERSION` поднимается до 3.** ⚠️ Оставить 2 нельзя: старая сборка приняла бы новый
  бэкап, молча выбросила `feedType` в `normalize()` и потеряла типы на первом же persist.
  Честный отказ (`version > SCHEMA_VERSION` → `null`) лучше тихой потери.
  Старые файлы (v1/v2) читаются как раньше.
- `normalize()` протаскивает `feedType`, отбрасывает неизвестные значения и ставит `undefined`
  для `kind='sleep'`. Кормление без типа показывается **без метки** — «грудь» по умолчанию
  не подставлять.

### ⚠️ `normalize()` обязан санировать ритм, а не только приводить типы

Через импорт `.lgbackup` сейчас проходит что угодно, минуя любые новые валидаторы:

1. `end < start` → запись отбрасывается.
2. Время в будущем (`start > now` или `end > now`) → отбрасывается.
3. Дубли `id` → дедуп, остаётся первая встреченная (иначе `update`/`remove` через `map`/`filter`
   тронут несколько записей одним тапом).
4. Несколько открытых записей одного вида (`end === null`) → открытой остаётся **самая свежая по
   `start`**, остальные отбрасываются.
5. Пересечения одноимённых записей → более поздняя по `start` отбрасывается.
6. Массив отдаётся отсортированным по `start` **убывающе**.

## 2. Действия стора

```ts
type RhythmError = 'endBeforeStart' | 'future' | 'overlap' | 'zeroLength';
updateRhythm(id, patch: { start?: number; end?: number | null; feedType?: FeedType }): RhythmError | null
addRhythmManual(kind, start, end: number | null, feedType?): RhythmError | null
removeRhythm(id): void
```

Валидатор общий, вынести в `lib/rhythm.ts`:
- интервалы **полуоткрытые** `[start, end)`; касание `A.end === B.start` пересечением НЕ считается;
- завершённая запись требует `end > start` строго (нулевой сон запрещён);
- будущее запрещено;
- два события **одного вида** не пересекаются; сон и кормление пересекаться могут;
- открытая запись при проверке пересечений считается интервалом `[start, now]`;
- ⚠️ при `updateRhythm` **сама редактируемая запись исключается** из проверки пересечений;
- при отказе состояние не меняется, UI показывает текст ошибки в карточке.

⚠️ `stopRhythm(kind)` сейчас закрывает **все** открытые записи вида (`map` по всем) —
чинить: закрывается только самая свежая по `start`.

⚠️ После `addRhythmManual` и после `updateRhythm` с изменением `start` массив **пересортировывается
по `start` убывающе**: экран кормления ищет последнее кормление через `.find()` по порядку массива.

## 3. Сутки, DST и подсчёт

Новый модуль `lib/rhythm.ts`:

- `dayBounds(key: string): { from: number; to: number }` — границы локальных суток через `Date`
  с `setHours(0,0,0,0)` для дня и следующего дня. ⚠️ **`from + 24h` использовать нельзя**: в сутки
  перехода на зимнее/летнее время их 23 или 25 часов, и полоса разъедется с местной полночью.
- Полоса суток масштабируется по фактической длине суток `to - from`, а не по константе 24 ч.
- `sleepMsOfDay(rhythm, key, now)` — сумма **пересечений** снов с сутками. Сон 21:30→06:10 даёт
  2:30 двадцать пятого и 6:10 двадцать шестого.
- `feedingsOfDay(rhythm, key)` — ⚠️ кормления считаются **по дню начала**, а НЕ по пересечению:
  иначе кормление через полночь попадёт в счётчик обоих дней. «6 кормлений» = 6 начатых.
- `sleepSegmentsOfDay(rhythm, key, now)` — отрезки для полосы, обрезанные по границам суток,
  с флагом `crossesNight`.
- ⚠️ Все функции принимают `now` **параметром**, не зовут `Date.now()` внутри: открытая запись
  иначе не пересчитается, а мемоизация по `rhythm` заморозит цифру.
- Ночь / день: **ночь = 20:00–08:00 местного времени** (решение владельца 26.08). Каждый отрезок
  сна режется этой границей, итог дня — «ночью X, днём Y в N снах». Никаких оценок.

⚠️ Дом (`app/(tabs)/index.tsx`) сейчас **не тикает вообще** и берёт `Date.now()` прямо в рендере:
при открытом сне цифра застывает, а после полуночи показывает вчерашние сутки. Дом получает
тикер с интервалом **1 минута** (не секунда), активный только при открытой записи, и пересчитывает
`dayKey` на каждом тике.

## 4. Экраны

### Общее для обоих разделов
- **Навигация по дням**: стрелки влево-вправо над полосой, вперёд дальше сегодня нельзя.
  ⚠️ `todayLabel(lang)` форматирует `new Date()` и заголовок ленты жёстко «СЕГОДНЯ» — заменить на
  `dayLabel(lang, date)` и подпись, зависящую от выбранного дня («Сегодня» / «Вчера» / дата).
- **Полоса суток** — общий компонент в `components/rhythm-shared.tsx` на `react-native-svg`:
  сон тёмными блоками, бодрствование светлым; кормления — засечки, интервалы между ними видны.
- ⚠️ Крупная карточка таймера и счётчик «не спит» относятся к **текущему моменту**, а не к
  выбранному дню: при просмотре прошедшего дня карточка таймера скрывается (лента и полоса
  остаются), кнопки «Уснул»/«Начали кормить» на прошлом дне не показываются.
- Лента под полосой: записи, пересекающие выбранный день; запись через полночь одна, с пометкой
  «через ночь».

### Сон
- Итог дня: «ночью X · днём Y в N снах».
- Счётчик «не спит 2:15» — время с конца последнего завершённого сна, только когда открытого сна
  нет и смотрим сегодняшний день. Чистый факт, без оценок.

### Кормление
- Итог дня: число кормлений.
- Тип кормления: грудь / бутылочка / прикорм — выбирается в карточке правки, показывается в ленте.
  Старые записи без типа — без метки.
- Карточка «последнее X назад» считается от реального сейчас, а не от выбранного дня.

## 5. Карточка правки — главное в этапе

Тап по строке ленты открывает карточку (модалка в стиле проекта, не Alert):
- Сон: «Уснул» / «Проснулся» / «Удалить».
- Кормление: «Начали» / «Закончили» / тип / «Удалить».
- Кнопка «+» над лентой открывает ту же карточку пустой — ручное добавление.
- Время задаётся **чипами «−15 / −30 / −1 ч»** от текущего момента, крупные цели: главный случай
  «вспомнил через двадцать минут» закрывается одним тапом, ночью, одной рукой.
- Тап по самому времени раскрывает системное колесо — зависимость
  `@react-native-community/datetimepicker`, ставить **через `npx expo install`** (версия из
  `bundledNativeModules.json`, в Expo Go 54 модуль уже есть).
- Ошибка валидации выводится в карточке текстом, состояние не меняется.

## 6. Полоска о забытом таймере — без пушей

Открытый сон дольше **5 ч** (кормление — **90 мин**) → при открытии раздела сверху полоска
с теми же чипами правки. Формулировка **про таймер, а не про ребёнка**:
«Таймер идёт 6:20 — всё ещё спит?». `expo-notifications` не подключаем, новых разрешений нет.
